Overview

The review of the original Compiler.py found a set of correctness bugs, missing protocol validation, and silent failure modes that made several filters compile to bytecode which behaved differently from tcpdump/libpcap. Every issue below is fixed in the updated file. The Lexer and Parser are untouched — all changes are scoped to the compiler and are marked with # FIX: comments in the source.

Verification target: after these fixes, the following filters compile to bytecode that matches tcpdump -d semantics and passes through the pure-Python BpfEmulator on real IPv4, IPv6, ARP, VLAN, and MPLS frames: tcp and port 80, tcp[13] & 2 != 0, host fe80::1, udp port 53, net 10.0.0.0, ip[2:2] > 500, (tcp or udp) and not dst port 53.

1  Critical Bugs

1.1  to_fprog() returned a dangling pointer

critical

The ctypes array backing the sock_fprog was a local variable and got garbage-collected before the caller could attach the filter to a socket. Any kernel SO_ATTACH_FILTER call was reading freed memory.

Before

insn_arr = arr_type()
# ... fill insn_arr ...
return sock_fprog(
    len(instructions),
    ctypes.cast(insn_arr, ctypes.POINTER(bpf_insn)),
)  # insn_arr dies here

After

insn_arr = arr_type()
# ... fill insn_arr ...
fprog = sock_fprog(
    len(instructions),
    ctypes.cast(insn_arr, ctypes.POINTER(bpf_insn)),
)
fprog._insn_arr = insn_arr  # keep alive
return fprog
Why it matters: Without this fix, attaching a compiled filter to a raw socket could crash, silently attach garbage, or be rejected by the kernel verifier.

1.2  Instruction.__repr__ raised ValueError

critical

The conditional expression was placed inside the format spec of an f-string, which is not valid Python format grammar. Any attempt to print an instruction (e.g. via disassemble or a REPL) raised an exception.

Before

f"... k=0x{self.k:x if isinstance(self.k, int)
                  else self.k})"  # ValueError

After

k_repr = f"0x{self.k:x}" if isinstance(self.k, int) \
         else str(self.k)
f"... k={k_repr})"  # ok

1.3  Classful net mask was computed incorrectly

critical

For a dotted-quad address like net 10.0.0.0, the original code computed prefix = len(parts) * 8 = 32, producing a /32 host route instead of the classful /8 that tcpdump uses.

Before

parts = str(node.value).split(".")
prefix = len(parts) * 8  # net 10.0.0.0 -> /32

After

if len(parts) == 4:
    first = int(parts[0])
    # Class A / B / C inference
    prefix = 8 if first < 128 else \
             16 if first < 192 else \
             24 if first < 224 else 32
else:
    prefix = len(parts) * 8
Why it matters: net 10.0.0.0 must match the whole 10.0.0.0/8 range, not a single host. This matches tcpdump’s documented classful behavior.

1.4  Byte access had no protocol guard

critical

Expressions such as tcp[13], ip[0], or icmp[icmptype] were compiled as bare ldb / ldh at fixed offsets. The filter would happily read TCP flags out of an ARP or IPv6 frame. libpcap always inserts an EtherType and IP-protocol check first.

Before (tcp[13] & 2 != 0)

(000) ldxb 4*([14]&0xf)
(001) ldb  [x + 27]   # no TCP check
(002) jset #2 ...

After (tcp[13] & 2 != 0)

(000) ldh  [12]              # EtherType?
(001) jeq  #0x800 ...
(002) ldb  [23]              # IP proto?
(003) jeq  #6 ...
(004) ldxb 4*([14]&0xf)
(005) ldb  [x + 27]
(006) jset #2 ...
Why it matters: Without guards, a filter like tcp[13] & 2 != 0 could produce false positives on any frame whose byte 27 happened to have bit 2 set.

1.5  Transport filters were IPv4-only

critical

_setup_transport_layer() rejected anything that was not EtherType 0x0800. As a result, tcp port 80, udp port 53, portrange 1000-2000, etc. could never match an IPv6 packet.

Before

ldh  [12]
jeq  #0x0800 ...      # IPv4 only
ldb  [23]
jeq  #<proto> ...
ldxb 4*([14]&0xf)

After

ldh  [12]
jeq  #0x0800, ipv4, ipv6   # dual-stack
# IPv4 path
  ldb [23]; jeq #<proto> ...
  ldxb 4*([14]&0xf)       # X = IHL
# IPv6 path
  ldb [20]; jeq #<proto> ...
  ldx  #40                  # X = 40 (fixed)
Why it matters: X is left holding the byte offset from the start of the packet to the transport header, so the same BPF_IND port loads work on both families.

1.6  inbound / outbound silently matched everything

critical

These direction qualifiers cannot be expressed in pure classic BPF without socket metadata. The original code compiled them to an unconditional jump to ACCEPT, meaning inbound and port 22 matched every packet, everywhere.

Before

elif kw in ("inbound", "outbound"):
    self._emit(Instruction(BPF_JMP | BPF_JA,
                            0, 0, true_target))  # matches all

After

elif kw in ("inbound", "outbound"):
    raise NotImplementedError(  # fail loudly
        f"'{kw}' requires socket metadata "
        f"and cannot be compiled to cBPF")

1.7  gateway had the wrong semantics

critical

gateway host in libpcap means “the packet’s Ethernet address matches the host’s, but its IP address does not” — i.e. the host forwarded it. The original code fell through to _compile_host_filter, matching the IP address, which is the opposite of the intended meaning.

Before

def _compile_gateway_filter(...):
    node.direction = None
    self._compile_host_filter(node, ...)  # wrong semantics

After

elif kw == "gateway":
    raise NotImplementedError(  # honest failure
        "'gateway' requires the host's MAC address, "
        "which is not resolvable at filter-compile time")

2  Correctness & Completeness Gaps

2.1  src and dst fell through to src or dst

high

Three filters handled src, dst, and the default (“either”) case, but omitted the explicit src and dst branch. That meant src and dst host 10.0.0.1 matched packets where only the source or only the destination matched.

  • _compile_host_filter — MAC address case
  • _compile_net_filter — IPv6 network case
  • _compile_portrange_filter — both directions

Before

if direction == "src":   ...
elif direction == "dst": ...
else:  # src-and-dst lands here too
    # "src or dst" logic

After

if direction == "src":   ...
elif direction == "dst": ...
elif direction == "src and dst":  # explicit
    # require both
else:
    # "src or dst" logic

2.2  Standalone pseudo-fields compiled to nonsense

high

FieldNode (tcpflags, icmptype, …) was treated as a value equal to its byte offset. So tcpflags == 2 compiled to “compare 13 to 2”, which is never true.

Before

elif isinstance(node, FieldNode):
    off, _ = FIELD_OFFSETS.get(node.name, (0, 1))
    self._emit(Instruction(BPF_LD | BPF_IMM,
                            0, 0, off))  # loads offset

After

elif isinstance(node, FieldNode):
    raise NotImplementedError(  # reject clearly
        f"Field '{node.name}' can only be used "
        f"inside a byte access (e.g. tcp[{node.name}])")

2.3  Division / modulo by a constant zero

high

BPF_DIV and BPF_MOD with k == 0 are rejected by the kernel verifier. The compiler emitted them anyway, so the resulting program could not be loaded.

Before

self._emit(Instruction(BPF_ALU | BPF_DIV | BPF_K,
                        0, 0, 0))  # invalid

After

if node.op in ("/", "%") and \
   isinstance(node.right, NumberNode) and \
   node.right.value == 0:
    raise ValueError(  # compile-time error
        "Division by zero in filter expression")

2.4  Jump offsets could silently overflow 8 bits

high

jt and jf are 8-bit fields in struct bpf_insn. A large and/or chain could produce offsets above 255, which struct.pack would silently truncate — corrupting every following jump.

Before

instr.jt = target_idx - (i + 1)
# silently truncated by struct.pack("B", ...)

After

instr.jt = target_idx - (i + 1)
if not (0 <= instr.jt <= 255):
    raise ValueError(  # fail loudly
        f"Conditional-jump true offset {instr.jt} "
        f"at insn {i} exceeds 8-bit range")

2.5  vlan only matched 0x8100

medium

The protocol check vlan accepted only the standard 802.1Q EtherType 0x8100 and missed the 802.1ad QinQ tag 0x88a8.

Before

ldh  [12]
jeq  #0x8100, ...  # only standard tag

After

ldh  [12]
jeq  #0x8100, vlan_ok, next
jeq  #0x88a8, vlan_ok, fail  # QinQ

2.6  icmp and icmp6 cross-matched IP versions

medium

ICMP over IPv4 has protocol number 1 and ICMP over IPv6 has next-header number 58. The original generic protocol path allowed icmp to match IPv6 next-header 1 (unused) and vice versa.

Before

# both go through the generic dual-stack path
ldh  [12]
jeq  #0x0800, ipv4, ipv6
# icmp   -> compares 1  against IPv6 next-header too
# icmp6  -> compares 58 against IPv4 proto byte too

After

# icmp: IPv4-only guard
jeq  #0x0800, ip4_ok, fail
ldb  [23]; jeq #1, ...

# icmp6: IPv6-only guard
jeq  #0x86DD, ip6_ok, fail
ldb  [20]; jeq #58, ...

2.7  Hostname resolution mutated the AST

low

_compile_host_filter overwrote node.value and node.value_type with the resolved IPv4 form, corrupting the AST. Compiling the same AST twice, or reusing a subtree, would produce different results.

Before

resolved_ip = socket.gethostbyname(node.value)
node.value = resolved_ip          # mutate caller's node
node.value_type = "ipv4"
self._compile_host_filter(node, ...)

After

resolved_ip = socket.gethostbyname(node.value)
clone = KeywordFilterNode(        # work on a copy
    keyword=node.keyword, value=resolved_ip,
    direction=node.direction, protocol=node.protocol,
    value_type="ipv4", mask=node.mask)
self._compile_host_filter(clone, ...)

3  Safety & Robustness

3.1  Fragile protocol-name resolution in _compile_proto_filter

medium

The original code tried int(value) first and only fell back to EtherType lookup if that raised. A name like 0x0800 would raise ValueError from the first branch and skip the fallback entirely. The rewrite classifies the token cleanly.

Before

proto_val = BpfLexer.IP_PROTOCOLS.get(proto_val.lower(), proto_val)
try:
    num = int(proto_val)
except ValueError:
    num = ETHERTYPE_MAP.get(proto_val.lower(), None)
# '0x0800' -> int(..., base 10) raises, skipped

After

if lv in BpfLexer.IP_PROTOCOLS: num = IP_PROTOCOLS[lv]
elif lv in ETHERTYPE_MAP:       num = ETHERTYPE_MAP[lv]
else:
    try:    num = int(lv, 0)  # base 0
    except ValueError: num = None

3.2  LiteralNode silently loaded 0

low

Unsupported literal kinds (IPv6 addresses, MACs, CIDRs in value position) compiled to ld #0 without any warning. Now they raise NotImplementedError, which surfaces as a clear user error instead of a filter that silently never matches.

3.3  IPCMPv6 in the dual-stack path

low

The icmp6 transport protocol was previously handled inside the generic dual-stack path, which also required IPv4 to be checked first. Now it is special-cased the same way as icmp, keeping the byte access paths symmetrical and easier to reason about.

5  What Was Not Changed

  • Lexer. No changes. The token set, regex ordering, and normalization rules are already consistent with the parser.
  • Parser. No changes. The recursive-descent grammar and AST shapes are preserved; the compiler now raises clear errors for the few constructs the parser permits but classic BPF cannot express.
  • Emulator. Only the __repr__ fix on Instruction affects it indirectly. The VM itself is unchanged.
  • Disassembler. No structural changes — it benefits from the __repr__ fix but the output format is identical.
Not implemented (by design). Several features require data that is not available at filter-compile time or that classic BPF cannot express: gateway (needs the host’s MAC), inbound/outbound (needs socket metadata), and protochain (needs IPv6 extension-header traversal). These now raise NotImplementedError instead of silently miscompiling.

6  Resulting Behavior

With the fixes in place, the following filters compile to bytecode that matches tcpdump -d semantics and round-trips correctly through the pure-Python BpfEmulator:

tcp and port 80
udp port 53

(tcp or udp) and not dst port 53
